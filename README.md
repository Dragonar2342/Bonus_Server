# Bonus Server

Простой REST-сервис для управления бонусами клиентов. Сервис позволяет начислять и списывать бонусы, выполнять возвраты операций, получать текущий баланс карты и историю операций.

Проект выполнен по этапам задания. Каждый этап должен фиксироваться отдельным коммитом или веткой.

## Основные сценарии

Сервис поддерживает следующие операции:

- начисление бонусов по карте клиента;
- списание бонусов по карте клиента;
- возврат ранее выполненной операции;
- получение баланса по номеру карты;
- получение истории операций по номеру карты.

## Этапы разработки

### Этап 1 — REST API и модель данных

Реализованы основные сценарии работы с бонусами:

- начисление;
- списание;
- возврат;
- получение баланса;
- получение истории операций.

Также спроектирована реляционная структура базы данных для карт и операций.

### Этап 2 — Миграции базы данных

Для управления структурой БД используется Flyway.

Миграции позволяют:

- создавать структуру базы данных;
- добавлять изменения в существующую БД;
- версионировать изменения схемы.

Миграции располагаются в:

```text
src/main/resources/db/migration/
```

### Этап 3 — Авторизация

Для доступа к API реализована авторизация.

Используются роли для разграничения операций чтения и изменения баланса.

Основные группы доступа:

- READ — получение баланса и истории операций;
- WRITE — изменение баланса и выполнение операций с бонусами.

### Этап 4 — Анализ и оптимизация запросов БД

Проведён анализ часто выполняемого запроса получения истории операций.

Исследовался запрос, выполняющий поиск операций карты с сортировкой:

```sql
ORDER BY bo.created_at DESC, bo.id DESC
LIMIT 20
```

В результате анализа был добавлен составной индекс:

```sql
CREATE INDEX idx_bonus_operation_card_created_id
ON bonus_operation (card_id, created_at DESC, id DESC);
```

## База данных

Основные таблицы проекта:

### `bonus_card`

Хранит бонусные карты клиентов.

Основные поля:

- `id` — идентификатор карты;
- `card_number` — номер карты;
- `balance` — текущий баланс;
- `created_at` — дата создания;
- `updated_at` — дата изменения.



### `bonus_operation`

Хранит историю операций по картам.

Основные поля:

- `id` — идентификатор операции;
- `card_id` — идентификатор карты;
- `operation_type` — тип операции;
- `amount` — сумма операции;
- `balance_change` — изменение баланса;
- `balance_after` — баланс после операции;
- `created_at` — дата операции;
- `reversal_of_operation_id` — ссылка на возвращаемую операцию.

## Запуск проекта

### Требования

- Java;
- PostgreSQL;
- Maven/Gradle в зависимости от конфигурации проекта.

Перед запуском необходимо настроить подключение приложения к PostgreSQL и параметры авторизации.

### Миграции

При запуске приложения Flyway применяет доступные миграции из:

```text
src/main/resources/db/migration/
```

После изменения схемы необходимо убедиться, что новая версия миграции успешно применена.

### API

Базовый URL локального API:

```text
http://localhost:8080
```

## Структура нагрузочного тестирования

Нагрузочный тест выполняется с помощью Apache JMeter.

В проекте используется отдельный JMeter-сценарий, содержащий функциональную часть и нагрузочные Thread Group.

Основной исследуемый endpoint:

```text
GET /api/v1/bonus-cards/{cardNumber}/operations?page=0&size=20
```

## Методика тестирования

Для проверки влияния индекса проводилось сравнение двух состояний БД:

```text
BEFORE — без дополнительного индекса
AFTER  — после добавления индекса
```

Измерялись следующие показатели:

- Average;
- 95 percentile;
- 99 percentile;
- Throughput;
- Error %.
